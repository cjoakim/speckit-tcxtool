# Implementation Plan: Timeline Page

**Branch**: `007-timeline-page` (feature id; work is currently on git branch `main`) | **Date**: 2026-11-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-timeline-page/spec.md`

## Summary

Feature 007 does two things:

- **States CSV (US1)**:
  - Three fields are added: StateTrackpointCount, ActivityDistanceMiles, and ActivityElapsedSeconds.
  - DistanceMiles becomes StateDistanceMiles.
  - The 16 fields are put in the draft's order.
  - The States page shows the new columns, and a feature 006 file counts as the wrong format.
- **Timeline page (US2, US3)**: the placeholder becomes a static SSR page with three parts:
  - a header card
  - a horizontal bar of the activity's StateSets, sized by elapsed time and colored by state
    (Q1 answer A, Q2 answer B), with a hover popup of a set's 16 values
  - three charts (Run Cadence, Heart Rate, Altitude), exactly as wide as the bar and aligned with it

**Technical approach** (details in research.md):

- **Parser**: `StatesCsvRow`, `StatesCsvWriter`, and `StatesCsvReader` move to 16 fields. The new
  values reuse the writer's `LastNonEmpty` and the set's count (R1).
  - The golden files are regenerated by the Python generator (R2).
  - A 13-field file is already a `HeaderMismatch`, so no new code is needed for old files (R3).
- **Geometry in C#**: a Web-side `TimelineLayout` turns the rows into fractions of the bar for every
  segment, center, and point, and a min and max for every chart (R4–R6).
  - All drawing rules are then unit tests, with no browser, as the constitution requires.
  - Alignment holds by construction, because all four drawings share one width and one margin pair.
- **Hand-off**: the page renders `<tcx-timeline data-timeline="JSON">`, and Blazor encodes the
  attribute (R7).
  - A small ES module, `wwwroot/js/timeline.js`, loaded in `App.razor`, defines the custom element.
    It works after both full loads and enhanced navigation.
  - D3 7.9.2 is imported only when the element exists (R8).
- **D3**: `d3.min.js` (the UMD bundle, since the package's `.mjs` only re-exports bare `d3-*` names; tasks.md T031 done note) and its ISC `LICENSE` are vendored under `wwwroot/lib/d3/`, with the npm
  integrity checked (R9).
- **Drawing** (R10–R12):
  - The bar is SVG rects with state classes, and it has a time axis.
  - The charts use `d3.axisLeft` over each chart's own domain, with circles and a thin gray
    `d3.line`.
  - The popup is found by bisecting on the pointer's x, filled through `textContent`, and closed by a
    click outside it.
  - The state colors live in `app.css` only.
- **Notices**: the States page's notice `switch` moves to a shared `StatesNotice` component, so the
  Timeline page shows exactly the same notices (R14).

## Technical Context

**Language/Version**: C# (ships with SDK 11.0.100), `net11.0`, pinned by `global.json`. Browser
code is one ES module, in plain modern JavaScript, with no build step.

**Primary Dependencies**:
- the ASP.NET Core and Blazor shared framework
- the vendored Bootstrap 5.3.0
- **D3.js 7.9.2** (ISC), new and vendored, as named by the constitution
- no new NuGet packages

**Storage**: files only. The States CSV format changes; the state file does not.

**Testing**:
- xUnit 2.9.3, bUnit 2.15.2, FluentAssertions 7.2.2, and `Microsoft.AspNetCore.Mvc.Testing` 11.0.0.
- HTTP tests use `TcxToolWebFactory`, and bUnit tests use `BunitTcxToolServices`.
- No JavaScript test runner, and no live browser (constitution Principle V). The browser behavior is
  checked by hand (quickstart scenario 5).

**Target Platform**: the macOS host (`dotnet run`), and the Linux container from `aspnet:11.0`.
Current desktop browsers (Safari, Chrome, Firefox) with ES modules, custom elements, and
`ResizeObserver`.

**Project Type**: Web application (Blazor Web App), with a parser class library and a test project.

**Performance Goals**:
- SC-002: the marathon's 541 StateSets are fully drawn in under 3 s.
- The server-side layout for 541 sets is built in under 100 ms, checked by a test.
- SC-004: the popup appears within 0.5 s.

**Constraints**:
- Static SSR, with no `@rendermode`.
- No network at runtime or in tests.
- No `<script>` inside a component (RZ9992), and no suppressed rules.
- The state colors are defined in one place.
- Tests never touch the real `data/csv/` or `tcxtool-state.json`, and use no real GPS positions.

**Scale/Scope**:
- One local user and one activity per page view.
- About 541 StateSets for a marathon, up to a few thousand for a long, stop-start activity.
- A JSON payload of about 150 KB for 541 sets.

**Structure Decision**: the existing three-project layout, with no change in project count:
- the parser library holds the States CSV format
- the Web project holds the Timeline layout, the components, and the browser assets
- the test project holds everything else

The new Web namespace is `Timeline`, which hides no BCL type that the app uses. This is the
`Convert` and `Activity` trap from features 002 and 005, and the first build after adding the folder
confirms it.
